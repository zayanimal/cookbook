# 8. Анализ принципов SOLID

## 8.1 S — Single Responsibility Principle (Принцип единственной ответственности)

> Каждый модуль должен иметь только одну причину для изменения.

### Соблюдается

| Модуль | Единственная ответственность |
|--------|------------------------------|
| `authService.js` | Только HTTP-запросы к `/auth/*` и работа с cookie |
| `sectionsService.js` | Только HTTP-запросы к ресурсу `sections` |
| `pagesService.js` | Только HTTP-запросы к ресурсу `pages` |
| `uiStore.js` | Только UI-состояние (выбор, сайдбар, ошибки) |
| `authStore.js` | Только бизнес-логика аутентификации |
| `slug.js` | Только транслитерация строки в URL-slug |
| `MermaidDiagram.jsx` | Только рендеринг Mermaid SVG |
| `ResizeHandle.jsx` | Только drag-resize сайдбара |
| `PrivateRoute.jsx` | Только защита маршрута |
| `LoginPage.jsx` | Только форма входа |

### Нарушения

| Модуль | Проблема |
|--------|---------|
| `MainLayout.jsx` | Содержит: оболочку приложения, логику URL-синхронизации, обработку keyboard shortcuts (Ctrl+K), управление видимостью header при скролле, обработку resize. Слишком много ответственностей в одном файле (358 строк). |
| `Sidebar.jsx` | Совмещает навигационное дерево, CRUD-диалоги и контекстное меню в 635 строках. |
| `PageView.jsx` | Редактор + просмотрщик + инлайн-редактирование заголовка + диалог удаления — всё в одном файле (432 строки). |
| `SearchDialog.jsx` | Содержит и UI-компонент, и алгоритм поиска (логику ранжирования результатов). |

## 8.2 O — Open/Closed Principle (Принцип открытости/закрытости)

> Программные сущности должны быть открыты для расширения, но закрыты для изменения.

### Соблюдается

**`codeBlockPlugin` с `codeBlockEditorDescriptors`:**
Добавление поддержки Mermaid реализовано без изменения существующего поведения редактора. Механизм дескрипторов позволяет расширять список языков без модификации ядра плагина.

```js
const mermaidDescriptor = {
  priority: 100,
  match: (language) => language === 'mermaid',
  Editor: MermaidBlockEditor,
}
```

**`api.js` + `mocks.js`:**
Переключение между mock и реальным API происходит через переменную окружения, без изменения кода сервисов.

### Нарушения

**`SearchDialog.jsx` — алгоритм поиска захардкожен:**
При необходимости добавить новый тип сущности в поиск нужно изменять алгоритм внутри компонента, вместо регистрации нового провайдера поиска.

**`Sidebar.jsx` — диалоги создания внутри компонента:**
Каждый новый тип сущности требует добавления нового диалога прямо в тело `Sidebar`, расширение закрыто.

## 8.3 L — Liskov Substitution Principle (Принцип подстановки Барбары Лисков)

> Объекты должны быть заменяемы на экземпляры подтипов без нарушения корректности.

### Соблюдается

**Mock API vs Real API:**
`mocks.js` полностью заменяет реальный API-клиент: одинаковый контракт (метод, URL, данные → ответ с `data`/`error`). Сервисы (`sectionsService`, etc.) работают одинаково в обоих режимах.

**`CodeBlockEditorDescriptor`:**
Любой кастомный дескриптор (например, `mermaidDescriptor`) полностью заменяет дефолтный рендерер для совпавшего языка, сохраняя интерфейс `Editor(code, language, meta, ...)`.

### Нарушения

**`pagesStore` — неявная зависимость на структуру `sectionsStore`:**
`pagesStore` напрямую мутирует `sectionsStore.sections[i].subsections[j].pages`, зная о внутренней структуре другого стора. Это создаёт жёсткую связь, которая нарушается при изменении внутреннего представления в `sectionsStore`.

---

## 8.4 I — Interface Segregation Principle (Принцип разделения интерфейсов)

> Клиенты не должны зависеть от методов, которые они не используют.

### Соблюдается

**Разделение сторов:**
Компоненты запрашивают только нужные сторы через `useStores()`:
- `LoginPage` → только `authStore`
- `PrivateRoute` → только `authStore`
- `PageView` → `cookbookStore` + `authStore`
- `EmptyState` → `cookbookStore` + `authStore`

**Computed-свойства в `authStore`:**
Компоненты не проверяют `user.role === 'admin'` напрямую — они используют `canEdit` / `canAdd`. При изменении ролевой модели менять нужно только `authStore`, не компоненты.

### Нарушения

**`cookbookStore` — избыточный фасад:**
Некоторые компоненты (`Sidebar`) вызывают через `cookbookStore` методы, которые по сути относятся к разным стором. Фасад даёт один большой интерфейс вместо нескольких узких. Компонент получает доступ ко всем методам сразу, хотя использует малую часть.

---

## 8.5 D — Dependency Inversion Principle (Принцип инверсии зависимостей)

> Модули верхнего уровня не должны зависеть от модулей нижнего. Оба должны зависеть от абстракций.

### Соблюдается

**Сервисы зависят от `api.js`, а не от конкретной реализации:**

```js
// sectionsService.js
import apiClient from './api'
const getAllSections = () => apiClient.get('/sections')
```

`apiClient` — абстракция, за которой может стоять как Axios, так и mock.

**Сторы зависят от сервисов (абстракция), а не от Axios:**
`sectionsStore` вызывает `sectionsService.getAllSections()`, не зная ничего об HTTP.

**React Context для сторов:**
Компоненты получают сторы через `useStores()` (Context), а не импортируют их напрямую. Это позволяет подменить сторы в тестах.

### Нарушения

**`pagesStore` напрямую импортирует `sectionsStore`-экземпляр:**
Вместо получения зависимости через конструктор или контекст, `pagesStore` хранит прямую ссылку на конкретный экземпляр `sectionsStore`. Это затрудняет изолированное тестирование `pagesStore`.

**Импорт `authService` в `api.js`:**
`api.js` импортирует `authService` для получения токена. Это создаёт циклическую потенциальную зависимость (api → authService → api). Правильнее передавать getter токена извне при инициализации клиента.

---

## 8.6 Сводная оценка

| Принцип | Оценка | Ключевые нарушения |
|---------|--------|--------------------|
| **S** — Single Responsibility | Частично | `MainLayout`, `Sidebar`, `PageView` — перегружены |
| **O** — Open/Closed | Хорошо | Архитектура дескрипторов и mock/real стратегия — пример хорошей расширяемости |
| **L** — Liskov Substitution | Хорошо | Mock полностью заменяет real API; нарушение в `pagesStore` |
| **I** — Interface Segregation | Частично | `cookbookStore`-фасад даёт слишком широкий интерфейс |
| **D** — Dependency Inversion | Хорошо | Сервисный слой через абстракции; нарушение в `pagesStore` и `api.js` |
