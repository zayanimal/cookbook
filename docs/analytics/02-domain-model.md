# 2. Доменная модель

## 2.1 Сущности и атрибуты

### User (Пользователь)

| Атрибут | Тип | Обязательный | Описание |
|---------|-----|:---:|----------|
| `id` | string | Да | Уникальный идентификатор |
| `username` | string | Да | Логин для входа |
| `role` | `admin` \| `client` | Да | Роль пользователя |
| `name` | string | Нет | Отображаемое имя |

---

### Section (Раздел)

| Атрибут | Тип | Обязательный | Описание |
|---------|-----|:---:|----------|
| `id` | string | Да | Уникальный идентификатор |
| `title` | string | Да | Название раздела |
| `subsections` | `Subsection[]` | Нет | Вложенные подразделы (lazy-load) |

---

### Subsection (Подраздел)

| Атрибут | Тип | Обязательный | Описание |
|---------|-----|:---:|----------|
| `id` | string | Да | Уникальный идентификатор |
| `title` | string | Да | Название подраздела |
| `pages` | `Page[]` | Нет | Вложенные страницы (lazy-load) |

---

### Page (Страница)

| Атрибут | Тип | Обязательный | Описание |
|---------|-----|:---:|----------|
| `id` | string | Да | Уникальный идентификатор |
| `title` | string | Да | Заголовок страницы |
| `content` | string | Да | Содержимое в формате Markdown |
| `createdAt` | ISO 8601 | Да | Дата создания |
| `updatedAt` | ISO 8601 | Да | Дата последнего изменения |

---

## 2.2 Диаграмма связей

```
┌──────────────┐
│     User     │
│  id          │
│  username    │
│  role        │
│  name        │
└──────┬───────┘
       │ аутентифицирует
       ▼
┌──────────────┐       1      ┌──────────────────┐
│   Section    │──────────────│   Subsection     │
│  id          │  содержит    │  id              │
│  title       │   (1..N)     │  title           │
│  subsections │◄─────────────│  pages           │
└──────────────┘              └────────┬─────────┘
                                       │ содержит (1..N)
                                       ▼
                              ┌──────────────────┐
                              │      Page        │
                              │  id              │
                              │  title           │
                              │  content (MD)    │
                              │  createdAt       │
                              │  updatedAt       │
                              └──────────────────┘
```

## 2.3 Иерархия контента

Контент организован в три уровня:

```
Раздел (Section)
└── Подраздел (Subsection)
    └── Страница (Page)
        └── Контент: Markdown
            ├── Заголовки, списки, таблицы
            ├── Блоки кода с подсветкой
            └── Диаграммы Mermaid
```

## 2.4 Формат идентификаторов

В mock API идентификаторы строятся по составному принципу, отражающему иерархию:

| Уровень | Формат | Пример |
|---------|--------|--------|
| Section | `{n}` | `"1"`, `"2"` |
| Subsection | `{sectionId}-{n}` | `"1-1"`, `"1-2"` |
| Page | `{sectionId}-{subsectionId}-{n}` | `"1-1-1"` |

> Реальный backend может использовать UUID или любой другой формат, так как фронтенд не зависит от структуры ID.

## 2.5 URL-адресация (slug)

Навигация в приложении реализована через человекочитаемые URL на основе транслитерации:

```
/:sectionSlug/:subsectionSlug/:pageSlug

Пример:
/otoplenie/kotel-i-radiatory/obshhaya-informaciya
```

Slug генерируется функцией `src/utils/slug.js` путём конвертации кириллицы в латиницу.

> Slug не хранится в БД — он вычисляется на лету из `title` сущности при каждой навигации.
